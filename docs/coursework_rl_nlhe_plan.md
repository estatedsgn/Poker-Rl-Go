# Roadmap: RL-агент для NLHE cash

## 1) Цель курсовой

Собрать пайплайн, где агент:
- получает наблюдение (стеки, история ставок, board cards, private cards, позиция, street);
- выдает действие (`fold`, `check`, `call`, `raise` + сайзинг);
- обучается в self-play и оценивается на фиксированном пуле оппонентов.

## 2) Рекомендуемая среда

### Вариант A (быстрый старт): RLCard
- Плюсы: быстрый запуск, готовые интерфейсы, много примеров.
- Минусы: abstraction среды и ограниченный контроль над реалистичными сайзингами.

### Вариант B (ближе к соревновательной задаче): кастомная NLHE-среда
- Библиотеки для правил/движка: `pokerkit` или аналогичный движок.
- Плюсы: полный контроль состояния, action masking, сайзинг-бакеты, логирование hand histories.
- Минусы: больше инженерки.

**Практика для курсовой:** начать с RLCard baseline, затем перейти на кастом/гибрид, если нужно усиление.

## 3) Формат пространства действий

Для RL-алгоритма используйте дискретный action space:
- `0 = fold`
- `1 = check/call` (в зависимости от контекста)
- `2..N = raise_bucket_i`

Вывод агента должен поддерживать:
- базовые действия: `fold`, `check`, `call`;
- рейз-сайзинги в долях банка от `0.01x` до `1.00x` (с шагом, например, `0.01` или `0.05`);
- отдельное действие `all-in`.

Обязательно используйте **action mask**, чтобы сеть не выбирала нелегальные действия.

## 4) Наблюдение (state encoding)

Минимум:
- one-hot street (`preflop/flop/turn/river`);
- позиция (`SB/BB/BTN/...`);
- effective stack (нормализованный в BB);
- pot size (в BB);
- to-call (в BB);
- private cards (ранк/масть, можно one-hot 52);
- board cards (one-hot 52);
- последние `K` действий (tokenized sequence).

## 5) Алгоритм обучения

Рекомендуемый baseline:
- PPO (стабильный старт, особенно с маской действий).

Для усиления:
- Recurrent PPO / Transformer policy (учет истории торговли);
- population-based self-play;
- league training (snapshot pool, best-response mix);
- curriculum по stack depth и числу игроков.

## 6) Метрики и оценка

- BB/100 на большом числе рук (минимум 100k-1M в оценке);
- winrate против фиксированного набора «замороженных» оппонентов;
- exploitability proxy (если доступно);
- стабильность по seed-ам.

## 7) План на 6–8 недель

1. Неделя 1: baseline env + random/legal agent + логирование.
2. Неделя 2: PPO baseline, action masking, первые кривые обучения.
3. Неделя 3: нормальный state encoder + сайзинг-бакеты.
4. Неделя 4: self-play и пул снапшотов.
5. Неделя 5: hyperparameter sweep.
6. Неделя 6: оценка против teacher agents (если есть API) + абляции.
7. Неделя 7–8: отчёт, графики, воспроизводимость.

## 8) Локально vs GPU-сервер

Локально (ноутбук):
- быстрые smoke-тесты, отладка среды, короткие прогоны.

GPU-сервер:
- большие self-play кампании;
- параллельные env workers;
- sweep гиперпараметров.

Рекомендации по запуску:
- фиксировать seed;
- логировать в Weights & Biases / TensorBoard;
- сохранять checkpoints каждые N итераций;
- версионировать конфиги (YAML/JSON).

- На каждом ходу среда должна отдавать legal actions, чтобы агент не выбирал запрещенные действия.
